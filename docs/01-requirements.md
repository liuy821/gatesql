# 需求与验收

本文档是 [产品文档](00-product.md) 的可执行版本。所有验收标准必须**可手动判定** —— 禁止「基本可用」「体验流畅」这类无法验证的表述。

## 一、能力清单

### P0 · 必做（没有它项目不成立）

**主链路**

| 能力 | 说明 |
|---|---|
| 端到端流式问答 | 提问 → 时间归一 → schema 切片 → 生成 SQL → 安全检查 → EQP 预检 → 口径检查 → 只读执行 → 表格 + 图表 + 结论。`app/api/chat/route.ts` 返回 `ReadableStream` 手写 SSE，显式 `runtime='nodejs'`、`dynamic='force-dynamic'`，响应头带 `X-Accel-Buffering: no` |
| SSE 事件协议作为唯一契约 | Zod discriminated union 定义事件类型，放共享模块，前端 / Route Handler / 评测脚本三方 import 同一份。前端 switch 加 `satisfies never` 穷尽检查，协议漂移变成编译失败 |
| `reduceEvents` 纯函数 | 把事件折叠成 `RunState` 的 reducer 提纯为无 React 依赖、无 IO 的函数。实时页用 `useReducer` 消费增量，`/runs` 历史页在服务端用同一函数折叠落库事件做 RSC 渲染 |
| 结果呈现 | 表格超 1000 行截断并明示，NULL 渲染为灰色「NULL」而非空白，数值右对齐千分位。图表由模型输出受 Zod 约束的极小 ChartSpec，前端做确定性编译，不匹配则降级为纯表格 |
| 七类错误态的界面处置 | `UNSAFE_SQL` / `COST_REJECTED` / `SQL_FAILED` / `NO_RELEVANT_TABLE` / `TIMEOUT` / `BUDGET_EXCEEDED` / `LLM_ERROR` 各有对应展示。任何路径下 `done` 事件保证必发 |
| schema 侧边栏 | 4 张表的中文注释、行数、数据时间范围、字段与注释，低基数字段展示全部枚举取值，点字段名可插入提问框 |

**安全（核心实现）**

| 能力 | 说明 |
|---|---|
| SQL 安全多层纵深 | 连接层 `readOnly` + 引擎层 `setAuthorizer` + 语句层 AST 白名单 + 强制 LIMIT。详见 [安全设计](07-security.md) |
| 全局禁用 `db.exec()` | 写一条扫源码的断言测试守住。`prepare()` 对多语句是静默只执行第一句、不报错，`exec()` 才是唯一真实多语句入口 |
| EQP 代价预检 | 执行前跑 `EXPLAIN QUERY PLAN`（约 1ms），结合各表行数量级判定是否缺失连接条件 |
| worker 隔离与超时放弃 | SQL 执行放进 worker，主线程自己计时。超时后直接返回 TIMEOUT，把该 worker 标记污染移出池，不等它退出 |
| 攻击语料测试集 | `tests/security/` 下 ≥30 条 Vitest 用例 |

**Agent**

| 能力 | 说明 |
|---|---|
| 手写 agent 主循环 | 含多维预算、指纹环路检测、失败六分类 |
| 口径规则引擎 | 8 条规则 + AST 谓词到达性检查，block 级回喂重生成，warn 级降级为「未核验」 |
| 规则误报率纪律 | 每条规则强制配正反两个 fixture，误报率作为一等指标上报，超 5% 的规则降级或删除 |
| 三态输出与拒答校准 | 已核验 / 未核验 / 拒答，四类确定性触发条件，四类歧义澄清模板 |
| AS_OF_DATE 单一时钟 | 默认取 `max(orders.created_at)` = 2026-08-31。相对时间由 date-fns 在进 LLM **之前**解析成绝对区间并回显 |
| schema 上下文工程 | 确定性裁剪（外键图 + 关键词匹配）+ 低基数列枚举值注入。**禁止向量检索** |
| 结构化输出容错解析 | Zod 定义 schema + 容错提取层（剥 markdown 围栏、修全角标点、去尾逗号）+ 一次带校验错误的自修 |
| 口径回执卡片 | 由 AST + 规则表机械生成的中文卡片，模型碰不到它 |

**评测**

| 能力 | 说明 |
|---|---|
| 30 题分层冻结评测集 | 六层各 5 题。题面在写实现代码前定稿并打 tag |
| 结果等价比对器 | 列名无关、列序无关、条件性行序、浮点容差、NULL/0/空串严格区分。**比对器本身必须有单测** |
| cassette 录制/回放 | 三模式 live / record / replay，一份基础设施三个用途 |
| 评测报告与优化日志 | `pnpm eval` 输出九项指标 + 「本轮由对转错的题号清单」 |

**工程**

| 能力 | 说明 |
|---|---|
| 可回放的结构化 trace | 落到物理隔离的 `app.db`，三张表 runs / steps / events |
| `/runs` 历史列表与详情页 | 可按失败 / 重试>0 / 被拒答筛选，逐步回放 |
| 鉴权与成本护栏 | 单口令 jose JWT + httpOnly cookie + middleware + IP 限流 + 日 token 预算（超限降级 replay 而非报错） |
| 一条命令启动 + 无 key 演示 | `output:'standalone'` + 多阶段 Dockerfile 单容器。不配 key 自动进 replay 模式 |
| README 与踩坑记录 | 30 秒 GIF、架构图、评测结果表格、三档如实分类、≥10 条踩坑记录 |
| Windows / GBK 适配 | 见 [工程规范](10-engineering.md) |

### P1 · 应做（有它才叫产品）

| 能力 | 说明 |
|---|---|
| 空结果归因探针 | 0 行时按启发式顺序逐层放宽跑 COUNT，定位是哪个条件把数据滤没。只跑 COUNT、最多 4 次、共用超时预算 |
| 数据水位与不完整周期检测 | 跨到未闭合周期的时间序列末点画虚线并标注 |
| SQL 人工编辑重跑 + 纠正样本回流 | 入库前过 guard 与 EQP，要求用户确认结果正确。检索用确定性打分。**必须做开/关两组对比评测** |
| 报表固化 | 一次问答保存为命名报表，重跑不调模型、约 200ms、零 token。用 Server Actions 实现 |
| CI 回归门禁 | GitHub Actions 在 replay 模式跑全量 30 题，掉点或回归则 PR fail。先观察一周再开 required check |
| `eval:quick` 与 LLM 磁盘缓存 | 10 题子集 90 秒跑完；按提示词哈希的磁盘缓存 |
| CSV 导出 | 流式生成，**带 UTF-8 BOM**（否则 Excel 打开中文乱码） |
| 架构决策记录（ADR） | 每个关键决策一篇，必须含「代价」一节 |

### P2 · 可选（第 7-8 周有余量才做）

聚合结果下钻到明细行 · 扰动数据库反过拟合 · 「以此问题为基础继续问」按钮 · Connector 接口接缝 + 硬化方案文档 · 站内 `/evals` 朴素表格页 · 表格虚拟滚动

## 二、用户故事与验收标准

| 编号 | 用户故事 | 验收标准（可手动判定） |
|---|---|---|
| US-1 | 我提一个简单问题，能看到答案 | 输入「一共有多少个客户」，依次出现状态条、SQL、表格、结论，返回 500，全程 ≤15 秒 |
| US-2 | 我能看到系统在思考 | 提问后 **800ms 内**出现第一个阶段事件，不是干等空白 |
| US-3 | 我能核对它怎么算的 | SQL 完整展示、带高亮、可复制；同时出现口径回执卡片，写明统计范围、已排除的订单状态及各自单数、用的是哪个价格字段 |
| US-4 | 趋势类问题能看到图 | 「每月销售额趋势」出折线图；「各分类销售额对比」出柱状图；「渠道占比」出饼图 |
| US-5 | 它写错 SQL 时能自己改对 | 输入「2026 年上半年各分类销售额」，界面上看到第 1 次尝试被 R1 拦下（显示缺失谓词）、第 2 次成功，两次尝试并列保留可对比 |
| US-6 | 恶意输入被拦住 | 输入「删除所有订单」→ 拒绝并说明只支持查询；`data/shop.db` 的 `orders` 表行数执行前后都是 12000 |
| US-7 | 问数据里没有的东西，有合理回复 | 输入「员工工资是多少」→ 进入拒答态，列出可查的 4 张表和 3 个示例问题，不编造、不报错、不返回空表 |
| US-8 | 口径歧义时它会问我 | 输入「上个月复购率多少」→ 给出两个澄清选项（自然月 / 90 天窗口）及各自口径说明，点选后沿用 |
| US-9 | 撞上数据边界不会误导我 | 输入「近 30 天销售额」→ 界面回显「已理解为 2026-08-02 ~ 2026-08-31」，而不是按 2026-09-11 算 |
| US-10 | 不完整的周期不会被读成暴跌 | 问跨到 9 月的月度趋势 → 最后一个点是虚线且标注「本期数据不完整」 |
| US-11 | 空结果时我知道为什么 | 构造必然空结果的问题（如华南地区 2024 年）→ 明确指出是哪个条件把数据滤没，并给出放宽后的行数 |
| US-12 | 刷新页面结果还在 | 关闭标签再打开 `/runs/[id]`，服务端渲染出完整内容，与实时看到的逐字一致 |
| US-13 | 我能纠正它 | 界面上改 SQL、重跑、保存为纠正样本；下次相似问题该样本被注入（trace 里可见） |
| US-14 | 常用问题不用重复问 | 保存为命名报表，点击重跑时 trace 里 `llm_call` 步骤数为 0、响应 <500ms |
| US-15 | 别人能跑起来我的项目 | 干净机器上 `git clone` + `docker compose up`，5 分钟内可提问；**不配任何 API key** 时预置 10 个问题全流程可跑 |

## 三、异常场景的预期行为

| 场景 | 预期行为 | 绝不允许 |
|---|---|---|
| 模型返回的 JSON 格式错误 | 容错提取（剥围栏、修全角标点）→ 带校验错误让模型自修一次 → 仍失败记 `SCHEMA_PARSE_FAILED` 走拒答 | 抛异常导致白屏 |
| 生成了危险语句 | guard 拦下，**不重试**（生成层失控，重试只烧钱），展示被拦语句和触发规则 | 静默丢弃或重试 |
| 缺失 JOIN 条件的笛卡尔积 | EQP 预检在执行前拒绝，给人类可读理由 | 交给超时兜底（实测三表笛卡尔积 120 秒不返回，会冻住整个事件循环） |
| 查询超时 | 主线程 5 秒后放弃等待，返回 TIMEOUT，该 worker 标记污染移出池 | 依赖 `worker.terminate()`（实测对卡在同步原生调用的 worker 永不 resolve） |
| 单次 run 超预算 | 优雅降级，优先级固定为 **数据正确性 > 结论 > 图表**：先砍图表、再砍结论，保留表格 + 回执 + 明确说明 | 返回半截答案却声称已核验 |
| 日 token 预算耗尽 | 整站降级到 cassette 回放模式 | 返回 500 |
| 模型在两个错误 SQL 间震荡 | 指纹环路检测命中 → 强制切换策略 → 再次命中则终止并落「未核验」 | 反复重试烧光配额 |
| 用户在提问里试图操纵 agent | prompt 注入防护 + guard 兜底，见 [安全设计](07-security.md) | 信任模型自律 |

## 四、非功能需求

| 项 | 目标 |
|---|---|
| 首个 SSE 事件延迟 | ≤800ms |
| 端到端 p50 / p95 | 记录并上报，不设硬指标（受模型速度支配） |
| 报表重跑 | <500ms，零 LLM 调用 |
| replay 模式跑全量 30 题 | <60 秒，零成本 |
| `eval:quick`（10 题） | <90 秒 |
| 结果行数上限 | 1000 行，超出截断并明示 |
| 查询超时 | 5 秒 |
| 单 run 预算 | maxLlmCalls=6，wallClockMs=45000 |

## 五、明确不做

这份清单和能力清单同等重要 —— 它是取舍能力的证据。分四类：

### 会通向另一个项目的

- **完整语义层**：QueryPlan IR、确定性 SQL 编译器、join 路径求解器、粒度冲突检测、方言编译层
- **治理与协作层**：指标注册表版本化、口径变更影响面分析、答案认证绿标、审核队列、评论、三角色 RBAC、审计日志导出、看板、答案永久链接快照
- **异步基础设施**：独立常驻 worker 进程、pg-boss 队列、LISTEN/NOTIFY 扇出、事件溯源、Last-Event-ID 断线续传
- **多数据源**：用户填 DSN、凭据 AES-GCM 加密、SSRF 校验与 DNS rebinding 防护、连接池 LRU
- **定时任务**：报表订阅推送、邮件、告警
- **智能洞察**：异常检测、归因分析、预测（「为什么这个月下降了」）—— 当前技术下最容易吹牛也最容易被戳穿的部分

### 已被实测证伪的

- **`better-sqlite3` + `db.interrupt()`**：13.0.3 根本没有 `interrupt` 方法；且即使有也不成立 —— db 句柄归 worker 所有，主线程无法调它的方法，而 worker 的事件循环正被同步原生调用堵死。另外它完全没有授权回调能力，还需要 node-gyp 原生编译（Windows + Docker 双重雷区）
- **依赖 `worker.terminate()` 做硬超时**：实测对卡在同步原生调用的 worker 15 秒不 resolve，随后 `process.exit(0)` 也无法让进程退出
- **`SQLite immutable=1`**：它让 SQLite 假定文件永不改变并跳过锁，重新 seed 后长连接会读到脏页。用 `{ readOnly: true }`
- **迁移到 PostgreSQL 换取安全叙事**：已实测 `node:sqlite` 的 `setAuthorizer` 可用，比只读角色更硬核也更便宜

### 会摧毁评测体系的

- **向量检索 / pgvector** 用于 few-shot 召回或 schema 检索 —— 引入不确定性，准确率变化再也无法归因
- **自由多轮追问 / 指代消解** —— 把评测从无状态变成有状态
- **`JSON.stringify(a)===JSON.stringify(b)` 做结果比对** —— 在浮点尾差、列名、列序、行序、int/decimal、NULL vs 0 上全部误判
- **LLM-as-judge 判定数值正确性** —— judge 最多用于评价结论文字可读性
- **只报一个准确率数字** —— 必须准确率、拒答率、自信错答率三者并列 + 分层 + 由对转错清单
- **把「拒答」和「模型说不知道」当成一回事**

### 投入产出比不成立的

- **任何 agent 框架**（LangChain / LangGraph / LlamaIndex）—— 一行 import 换掉整个项目的核心价值
- **多 agent 编排 / planner + critic** —— 只是叠加不确定性
- **Auth.js / NextAuth + OAuth** —— 几天样板配置换零简历价值
- **OpenTelemetry + Jaeger + Prometheus/Grafana** —— 单进程项目里是纯炫技，每多一个容器就是多一份「面试官 `docker compose up` 失败」的概率
- **120 题评测集** —— 手写 gold SQL 是被最严重低估的工时，30 题足够支撑全部叙事
- **每题跑 3 次取多数** —— 3 倍 token 换作品集不需要的精度
- **Vercel 作为主部署** —— serverless 文件系统只读且实例间不共享，`app.db` 写不进去
- **Kubernetes / Helm / Terraform** —— 单人项目引入这些是自证不懂取舍
- **Playwright 全量 E2E / 追求覆盖率数字** —— 测试只押在「写错了会静默产生错误结论」的地方
- **UI 打磨**：移动端提问交互、i18n、自定义主题、深色模式、动画、自建设计系统 —— 一律 shadcn/ui 默认外观，设硬性时间盒，超时砍功能而不是延期
- **站内 `/evals` 趋势图与热力图** —— 零边际价值的纯 CSS 时间
- **Excel / PDF 导出、报表模板、图表二次编辑、看板拖拽** —— 只保留 CSV
- **模型微调 / 本地部署 / 多模型对比 UI / 多模态** —— 项目当前可用的是纯文本模型，视觉能力是硬约束

### 绝对禁止

- **agent 代码路径上出现 `db.exec()`** —— 写一条断言测试守住。实测 `prepare()` 对多语句静默截断，`exec()` 是唯一真实多语句入口。这一条若破防，前面所有 AST 白名单全部白做
- **正则/关键字黑名单作为 SQL 主防线** —— 只保留为最廉价的前置过滤
- **让模型直出 ECharts option JSON** —— 字段空间无限大、校验不可能完备、一个笔误就是运行时白屏
